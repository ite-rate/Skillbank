# 会话操作

使用 `session_status` 定位目标会话及其待处理请求，再用 `session_continue` 回答问题或处理权限。始终先展示查询结果，取得用户明确确认后再执行，并在操作后复查状态。

## 交互方式

所有需要用户选择、补充答案或确认执行的步骤，都必须通过 Markdown 表格和普通自然语言消息完成。不得调用 `question`、question-tool 或其他结构化反问组件向用户提问。

- 有多个候选项时，使用 Markdown 表格逐项编号，并提示用户在普通消息中回复序号或具体内容。
- 需要自由文本答案时，直接用自然语言说明所需信息，等待用户在普通消息中回复。
- 执行前确认必须展示完整方案，并用自然语言询问用户是否确认；不得使用按钮、单选框或其他交互组件代替明确回复。
- 此限制仅适用于当前会话中向用户收集信息；处理目标会话已有的待回答问题时，仍按下文要求使用 `session_continue` 提交答案。

## 工作流

1. 调用 `session_status` 查询最近会话。默认使用 `limit: 10` 和 `page: 1`；需要扩大范围时继续翻页。将 `limit` 视为每页上限，将 `number` 视为当前页实际数量。
2. 查询后必须立即使用 Markdown 表格展示会话信息，便于用户选择。不要只复述会话数量或返回原始 JSON。
3. 根据用户选择及内部保留的会话 `id`、`title` 和 `query` 确认唯一目标。候选不唯一时，要求用户按本次查询结果中的序号选择，不要猜测，也不要在候选会话表格中展示具体的会话 ID。
4. 检查目标的 `status` 和 `pending`：
   - `needs_human`：根据待处理请求准备操作方案。
   - `running` 或 `retrying`：报告当前状态，不要伪造介入请求。
   - `idle`：报告没有可解除的阻塞。`session_continue` 不能向未阻塞会话追加普通消息。
5. 展示拟执行的会话、`requestID`、问题答案或权限动作及其影响，询问用户是否确认执行。此步骤只展示方案，不得调用 `session_continue`。
6. 仅在用户明确回复确认后，使用明确的 `requestID` 调用 `session_continue`。用户修改答案、反馈或权限动作时，更新方案并重新确认。
7. 再次调用 `session_status`，确认请求已经解除或发现新的待处理请求。简洁报告实际结果。

## 展示会话

使用以下 Markdown 表格结构。将多行文本压缩为简短单行，转义会破坏表格的 `|` 字符；不要虚构缺失字段。不得在表格中展示完整或部分会话 ID。序号仅对应本次查询结果，必须在内部保留序号到真实会话 ID 的映射，供后续唯一定位和工具调用使用。

| 序号 | 标题 | 状态 | 最近请求 | 待处理 |
| ---: | --- | --- | --- | --- |
| 1 | 发布桌面应用 | `needs_human` | 执行发布流程 | 权限 `per_xxx` |
| 2 | 修复登录问题 | `running` | 排查登录失败 | 无 |

表格后明确提示用户使用序号选择。若用户已指定唯一会话，仍需展示包含该会话的表格，再进入操作确认阶段。

## 执行前确认

调用 `session_continue` 前必须单独向用户确认。确认内容需要包含：

- 待处理问题、以及最近请求内容。
- 将提交的完整答案，或权限的 `reply` 与反馈文本。
- 操作影响，例如“仅批准本次请求”或“拒绝并把反馈交回原会话”。

且不要在确认内容中展示完整或部分session ID和request ID。
使用清晰问题结束确认，例如：“确认按以上内容继续该会话吗？”没有得到明确肯定答复时，不要调用 `session_continue`。不得把用户最初的查询请求视为执行确认。

## 回答问题

读取待处理问题中的 `questions`，按原顺序构造二维 `answers`。每个问题对应一个字符串数组：单选通常一个值，多选可以有多个值。

使用“其他/自定义输入”时，直接把实际文本放入答案数组，不要传递 `Other`、`其他` 或界面占位文案：

仅有一个问题时，可以省略 `answers` 并用顶层 `text` 作为回退；优先使用显式 `answers`。

## 处理权限

始终显式指定 `reply`：

- 使用 `once` 仅批准当前请求。
- 仅在用户明确要求并再次确认后使用 `always`。
- 使用 `reject` 拒绝请求；需要调整任务时，将追加指令放入顶层 `text` 作为反馈。



## 安全约束

- 仅操作用户指定或已唯一确认的其他会话。
- 不要把 `session_status` 返回的当前页数量 `number` 当作总会话数。
- 不要依赖“第一个待处理请求”的隐式选择。
- 不要重复回复已经处理的 `requestID`；遇到 `not_blocked` 或 `skipped` 时停止并重新查询。
- 不要声称普通指令已发送给 `idle` 或 `running` 会话；当前工具只处理问题和权限阻塞。
- 不要使用 question-tool 或其他结构化反问组件进行会话选择、答案收集或执行确认。
- 未获得本轮明确确认时，绝不调用 `session_continue`。
