# Thoughtcode (Go 版)

## 何时用

用户读 Go 源码、刷题、或讨论实现时,要求**省掉语法噪音、只保留意图和结构骨架**,让大脑零语法解析。源码层交给 LLM/工具处理,人类面对思路码。

## 思路码是什么

不是理念层(那是设计文档),不是缩水源码(那只是去字符),是**结构骨架保留 + 动作整句中文化** 的中间层:
- 读思路码能在脑里浮出对应 Go 源码(保真)
- 读思路码不做任何语法解析(零噪音)

判据:读者读完一行,有没有在脑子里跑"语法解析器"?有 → 噪音没去干净。没有 → 合格。

## 翻译规则(硬约束,违反就算不合格)

### 保留(Go 语义的一部分,丢了对应不上源码)
- **函数边界**:`func foo(x, y):` 这种签名保留,函数名和参数名在,参数类型可省(类型信息放进字段声明)
- **字段声明**:`字段 mu (sync.Mutex) 保护 counts` —— 字段名 + 类型(类型决定行为)+ 一句意图
- **控制流关键字**:`for` / `if` / `return` / `break` / `continue` 保留(英文短关键字,不是噪音)
- **赋值 `=`**:语义透明
- **单层成员访问 `a.b`**:保留,但 `a.b.c` 必须拆开(见下)
- **算术和比较**:`+ - * / %` `== != < > >= <=` 保留(数学语义)
- **数学函数 `max(a,b)` `min(a,b)` `len(s)`**:保留,语义透明,嵌套也行(`max(gain(左子), 0)` 允许,因为数学函数调用无副作用语义)

### 禁止(强制中文化,出现即重写)
- **C 系运算符**:`?:` `&&` `||` `!` `++` `--` `->`
  - `a ? b : c` → `a 真 则 b 否则 c` 或拆成两行
  - `a && b` → `a 且 b`
  - `a || b` → `a 或 b`
  - `!a` → `a 不成立` 或 `非a`
  - `a++` → `a 加一`
- **方法调用语法**:`stack.push(x)` → `x 压栈` 或 `x 入栈`;`res.append(v)` → `v 追加到 res` 或 `res 加 v`;`q.pop_front()` → `队首出队`
  - 动作用中文动词,主语宾语自然成句
  - 例外:`strings.Split`、`json.Marshal` 这种标准库函数,保留 `Split(s, ",")` 形式(名字即意图,翻译反而失真)
- **连续点访问 `a.b.c`**:拆开加中间变量
  - `p.Next.Next` → `next = p.Next; nextNext = next.Next`(或 `next = p的下一个; nextNext = next的下一个`)
- **嵌套调用 `f(g(h(x)))`**:拆开
  - 例外:数学函数嵌套见上
- **类型声明中的复杂语法**:`func (s *Server) handleX(w http.ResponseWriter, r *http.Request)` 这种长签名 → 简化
  - → `handleX(w, r):  Server 的方法`(参数名保留,类型收进字段表或省略,接收者用一句标)
- **`nil` 检查的啰嗦形式**:`if err != nil { ... }` → `err 不空, ...`
- **多行 if/else 块**:压成一行"条件真则...否则..."

### 边界情况
- **defer**:`defer cancel()` → `defer cancel()` 保留(语义不可替代),或 `defer 取消`(中文也行,但要一致)
- **go 关键字**:`go func(){...}()` → `起 goroutine 跑 ...` 保留并发语义
- **channel**:`ch <- v` → `v 送入 ch`;`v := <-ch` → `ch 取出给 v`;`close(ch)` → `ch 关闭`
- **interface 断言**:`v, ok := x.(T)` → `x 断言为 T 给 v, ok 存`
- **range**:`for i, v := range arr` → `for i, v 遍历 arr`

## 翻译模板(按代码类型)

### 数据结构
```
Go 结构体 <Name>:
  字段 <字段名> (<类型>)  <一句话意图或属性>
  字段 ...
```

### 函数(短)
```
<func名>(<参数>):  <一句话功能>
  <动作>  <意图注释>
  <动作>
  返回 <什么>
```

### 函数(长,有逻辑分支)
```
<func名>(<参数>):
  <步骤1>  <意图>
  for <条件>:
    <动作>
    if <条件>: <动作>
    <动作>
  返回 <什么>
```

### 算法题
```
<编号>. <题目名>

<一句话题意>

<主函数名>(<参数>):
  <步骤>
  ...
  返回 <什么>

关键点:
- <源码里看不出来但影响行为的点,每条一行>
```

### 多文件/模块(像 mini_ros2 那种)
```
<模块名>:
  <责任一句话 + 核心数据结构>
  <对外接口,每条一行意图>
  并发约束: <一句话>

<调用方/main>:
  <一串动作,每步一句意图,带关键数字>

漏掉的处理:
- <源码里没做但影响行为的点,每条一行>
```

## 工作流(用户触发后)

1. **判断输入形态**:
   - 用户给 Go 源码 → 翻译成思路码
   - 用户给题目/需求 → 直接写思路码
   - 用户说"过一下 leetcode 链表题" → 按题型清单逐题写思路码
2. **翻译时**:按硬约束逐条过,任何违反立即重写,不要混用(出现一处 `&&` 整份不合格)
3. **写完后**:如果用户在审粒度,主动指出**本份里有歧义的几行**,问"这几行该更紧还是更松"——粒度是用户定的,不是翻译器定的
4. **不要做的事**:
   - 不要给源码(用户明说要源码才给)
   - 不要给"决策/代价/为什么"的理念层(那是另一套,用户明确要了才加)
   - 不要加版本控制/测试/规范(思路码是阅读产物,不是工程产物)

## 粒度校准线(关键,这是用户反复纠正出来的)

粒度由用户定,但翻译器有默认校准线:

- **默认粒度**:函数边界全保留(`func foo():`),函数体内每行"动作 + 意图"合一
- **更紧的粒度**(用户可要求):短函数压成一行 `foo(): 一句话描述`
- **更松的粒度**(用户可要求):保留每行 Go 的赋值,只去运算符噪音

用户给过示例样本(见 references/samples.md),翻译时**对照样本定粒度**,不要自己挑。如果用户给的样本和默认粒度冲突,**以用户样本为准**。

## 参考样本(必须读)

具体粒度由样本决定。读 `references/samples.md` 看已校准的样本(94 中序遍历、Go HTTP server、mini_ros2 pub_sub)。每次翻译前对照样本,确保粒度一致。

## 限制

- **只支持 Go**(2026-07-26)。其他语言(C++/Rust/Python)用户明确要求再扩,且要单独定规则(每种语言的"语法噪音"定义不同)
- **不是设计文档工具**:不输出"为什么这么设计/代价/取舍"。用户要那层,显式说"加理念层",再叠上去
- **不验证正确性**:思路码是阅读产物,不保证算法对、不保证能跑。验证靠测试或 LLM 实现
- **保真度靠人工审**:翻译器不保证 100% 等价于源码,用户审"信息有没有丢"。翻译器只保证"按规则翻译"
