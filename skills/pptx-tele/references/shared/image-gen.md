# AI 生图 — PPT 场景策略

本文档定义 PPT Skill 中所有生图调用的场景策略，包括PPT 场景下的选型、策略和兜底规则。排版 `.pptx`、网页演示和图片 PPT 都必须先阅读本文件，再按对应 workflow 继续执行。

## 两种模式

- **文生图**：从文本 prompt 生成图片。配图方案由用户在需求澄清中选定，Agent 不得自行决定是否生成候选。
- **图生图 / 参考图编辑**：传入参考图，延续风格或局部改写。该模式不支持生成多张候选；适合在确定风格样张后批量保持画风一致。

## 比例与推荐尺寸

根据页面中图片槽位的实际比例和用途选择生图尺寸。选择尺寸时必须同时满足两个条件：宽高比与目标布局一致，且总像素在生图工具允许范围内。

**尺寸约束**（由生图工具定义）：总像素范围 3,686,400 至 16,777,216；宽高比范围 1:16 至 16:1。低于最小像素的尺寸会被工具拒绝，不得使用。

**推荐尺寸**（宽x高，均为满足约束的最小合规值，更大尺寸亦可）：

| 比例 | 推荐尺寸 | 典型用途 |
|------|---------|---------|
| 1:1 | 1920x1920 | 图标、小装饰、方形纹理 |
| 4:3 | 2240x1680 | 左文右图、内容配图、照片 |
| 3:4 | 1680x2240 | 竖版人物、窄图槽位 |
| 16:9 | 2560x1440 | 全页背景、封面、hero 图 |
| 9:16 | 1440x2560 | 手机界面、竖屏场景 |
| 3:2 | 2400x1600 | 摄影感配图、宽图槽位 |
| 2:3 | 1600x2400 | 竖版人物、竖版海报 |
| 21:9 | 3024x1296 | 超宽横幅、氛围背景 |

纯图片 PPT 所有页面统一使用 16:9 横向比例。生成图片的宽高比必须与目标幻灯片布局比例严格一致，不一致将导致图片溢出裁切或黑边变形。

**尺寸校验**：调用生图工具前，确认宽×高的乘积在 [3,686,400, 16,777,216] 范围内。不在范围内的尺寸将被工具拒绝，必须调整后重试。

## 调用策略

- 计划生成前必须在执行摘要或生图计划中写明预计图片张数。
- 若生图服务返回额度或可用性限制，告知用户当前状况并请其选择减少图片数、改用原生组件或切换路线，不做无意义重试。生图额度每日重置，不得基于对话记忆推断额度已耗尽——必须实际尝试生图后，确认知服务当前返回了额度限制错误，才可告知用户。
- 结果明显不遵循 prompt 要求时，可提高提示词遵循程度后重试，不默认拉高。

## 配图清单（image-plan.md）

布局规划完成后、生图之前，必须生成一份配图清单文件作为后续所有环节的唯⼀依据：

```text
{工作目录}/.temp/image-plan.md
```

### 生成时机

配图清单在布局规划阶段生成，此时每页的图片槽位比例已经确定。

**HTML 路线**：配图清单在布局选型完成后生成，此时每页的布局和图片槽位已确定。清单中只能包含有图片槽位的页面；无槽位的页面不应列入（避免生成后无法放置）。清单字段与 `.pptx` 路线相同，额外增加一列"HTML 槽位 class"标记目标布局中的图片容器（如 `.frame-img.r-16x10`、`.hero-img-wrap`）。

### 文件格式

```markdown
# {项目名} 配图清单

| 页码 | 主题 | 图片内容描述 | 像素比 | 生图尺寸 | HTML 槽位 class | 状态 | 文件名 |
|------|------|-------------|--------|---------|----------------|------|--------|
| 1 | 封面 | 青花瓷花瓶特写，浅色背景 | 16:9 | 2560x1440 | | 待生成 | |
| 5 | 明清巅峰 | 明代青花瓷瓶，深蓝底 | 4:3 | 2240x1680 | .frame-img.r-4x3 | 待生成 | |
| 11 | 唐诗文学 | 书法卷轴与墨砚 | 1:1 | 1920x1920 | | 待生成 | |
```

字段说明：
- **像素比**：由该页布局中的图片槽位宽高比决定（如左文右图区域占一半，槽位比例约4:3；全屏背景则为16:9）。
- **生图尺寸**：根据像素比从"推荐尺寸"表查得，必须与像素比对应。
- **状态**：待生成 → 已生成 → 已校验。
- **文件名**：生图完成后填入语义文件名（见"生成后立即重命名"章节）。

### 强制读取规则

以下两个环节开始前，必须重新读取 `image-plan.md`，不得凭记忆操作：

1. **生图环节**：读取清单，确认每张图的像素比和生图尺寸，按清单参数调用 ImageGen。禁止全部使用同一默认尺寸。
2. **脚本编写环节**：读取清单，确认每张图的像素比，addImage 的 w/h 比必须与清单中像素比一致（误差 < 1%）。

### 生成后校验

图片全部生成并重命名后、组装最终交付物之前，基于 `image-plan.md` 做以下校验：

1. **比例一致性**：每张图的 addImage w/h 比 vs 清单像素比，abs 差值 > 0.01 即为不一致，必须修正。
2. **文件名匹配**：脚本中引用的图片文件名 vs 清单中的文件名，必须一一对应。
3. **张数一致**：清单行数 vs 实际生成张数，不得静默减少。

校验不通过的项必须修正后才能继续组装，不得跳过。

## 生成后立即重命名

并行生图时，每个 TOOL_RESULT 的 callID 能明确追溯到发起调用时的 prompt，prompt→文件名的对应关系是清晰的。但默认文件名（如 `seedream-xxx-87443ef8.jpg`）无语义，在长上下文下极易混淆或被遗忘，导致后续组装时凭记忆重新分配而出错。

**强制规则：每批 ImageGen 返回后，在同一轮内立刻完成重命名**，根据 callID 对应的 prompt 语义，将无语义的默认文件名改为携带页码和主题的语义文件名，并回填到 `image-plan.md` 的文件名列。

重命名格式：

```text
{工作目录}/.temp/images/slide-{页码}-{主题关键词}.{ext}
```

示例：

```powershell
Rename-Item "seedream-20260527071532-01-0f39797d.jpg" "slide-10-丝绸之路.jpg"
```

要求：

- 页码与 `image-plan.md` 中的页码严格一致。
- 主题关键词从该页的 ImageGen prompt 语义中提取，2-6 个汉字即可，无需完整标题。
- 重命名必须在 ImageGen 返回的同一轮执行，不能推迟到后续步骤再做。
- 重命名后，后续脚本和代码只能引用语义文件名，禁止出现原始 `seedream-xxx` 文件名。
- 重命名后立即更新 `image-plan.md` 中对应行的文件名和状态字段。

## 风格锚定

同一份 deck 的 AI 图片必须保持一致的画风、色调和构图密度。

- 所有图片共用一组风格前缀 prompt。
- 优先生成或选择一张无文字风格样张作为参考图，再用图生图模式生成后续图片。
- 不要默认使用第一张正文页成品图作参考，避免把正文文字、错误布局或页面专属元素污染到后续页。
- 参考图只能是图片格式（png、jpg、jpeg、webp），支持本地路径、HTTP/HTTPS URL 或 `data:image/...;base64,...`。
- 不能直接把 `.ppt`、`.pptx`、PDF 或其他非图片文件作为参考图；如需参考 PPT 页面，先导出为图片。

## 输出路径

`.pptx` 链路中的图片是过程文件：

```text
{工作目录}/.temp/images/
```

PptxGenJS 会把 `slide.addImage({ path })` 和 `slide.background = { path }` 引用的图片内嵌到最终 `.pptx`。只有在 `.pptx` 成功生成并完成 QA 后，源图片才可删除。

HTML 链路中的图片是最终交付物的一部分：

```text
{工作目录}/{项目名}/images/
```

HTML 使用相对路径引用图片，不能只交付单个 `index.html`。

## 图像校验

所有链路生成图片后、组装最终交付物之前，必须使用图像理解能力对每张图片进行校验，确认图片内容与预期一致。校验可并行执行。

请注意，生图工具返回的图片**默认带有平台合规水印**，这是服务侧强制要求，不是 prompt 失误，也不是画面质量问题。

- **不要**因出现该水印而判定为 FAIL、WARN，或触发重试、降级。
- **不要**在 prompt 中要求模型「去掉水印」或反复重试以消除水印；无法通过改 prompt 去除。
- prompt 中的「不要生成水印」仅指**画面内容里**不要额外绘制伪 logo、版权角标、页眉页脚式水印等；与上述**服务合规水印**不是同一类问题。

图像校验、thumbnail QA、人工目视检查时，均须将合规水印视为**预期现象**，单独记录即可，不得计入 issues 或作为不合格依据。

### 校验提示词模板（通用）

```text
你是一位PPT质量审核员。请对这张幻灯片图片进行校验，严格对照以下内容清单逐项检查。

页面类型：{page_type}
预期文字清单：{text_list}

检查项：
1. 文字完整性：清单中的每段文字是否都在图片中出现？有无缺失或被裁切？
2. 文字准确性：出现的文字是否与清单一致？有无错字、乱码、多余文字？
3. 画面完整性：画面四周是否有安全边距？关键内容是否被裁切？有无黑边？
4. 画面清洁度：是否出现伪 logo、模型自绘的版权角标/页眉页脚式水印、无意义字符？**忽略**生图服务默认的合规水印（见「合规水印（生图服务默认）」），其存在不算问题。
5. 文字逐字核对：逐一将图片中出现的每个字符与清单原文对比，标注所有不一致的字。重点关注：形近字替换（如鸦→鸡、徐→除、己/已/巳混淆）、同音替换、偏旁增减、数字/符号偏移、英文拼写错误。输出格式："原文X → 图中Y（位置描述）"。
6. 文字重复检测：清单中每段文字在图片中是否出现了超过一次？文字重复是AI生图常见缺陷，
    - 图片中同一标题、同一要点出现两次即属重复，即使重复的文字本身正确也算问题。
    - 输出格式："文字X 重复出现N次（位置描述）"。

status 判定标准：
- PASS：所有检查项无问题。
- WARN：存在轻微问题（小裁切、非关键文字有细微偏差），不影响整体理解。出现1个非关键字符偏差（如装饰性副文案）且不影响核心信息传达。
- FAIL：存在严重问题（关键文字缺失、大面积乱码、构图完全偏离预期），影响信息传达。清单中明确要求的文字出现错字（如主标题、人名、专有名词、数字、品牌词）即判 FAIL；标题、要点等关键文字重复出现亦判 FAIL。

输出格式（必须严格遵守）：
- status: PASS / WARN / FAIL
- issues: 逐条列出发现的问题，无问题则写"无"
- missing_texts: 未出现的文字列表，无则写"无"
- extra_texts: 清单外出现的文字列表，无则写"无"
- wrong_chars: 与清单不一致的字符列表，格式为"原文→图中文（位置）"，无则写"无"
- duplicated_texts: 重复出现的文字列表，格式为"文字 重复N次（位置）"，无则写"无"
```

### 页面类型附加检查

在通用模板末尾，按页面类型追加对应的检查项：

| 页面类型 | 附加检查项 |
|---------|-----------|
| `cover` | 主标题是否大而清晰、是否居中或位于指定位置、副标题是否可读 |
| `content` | 2-3个核心要点是否都可见、图标/连线是否与要点对应 |
| `data` | KPI数字是否可读且无乱码、图表区域是否有明显渲染错误 |
| `closing` | 总结/行动号召文字是否清晰可读、画面收束效果是否正常 |

### 校验结果分级处理

| status | 处理 |
|--------|------|
| PASS | 继续 |
| WARN | 记录问题，继续组装，不重试 |
| FAIL | 判定 FAIL 类型后执行对应重试策略（见下表） |

### FAIL 类型与重试策略

| FAIL 类型 | 判定依据 | 重试策略 | 最大重试次数 |
|-----------|---------|---------|------------|
| 文字错字/拼写错误 | wrong_chars 非空，且为关键文字 | **修正 prompt 后重试**：将 wrong_chars 中的错误加入 prompt 的"关键文字准确性强调区"，提高 guidance_scale 至 3.5~4.5 | 1次 |
| 文字缺失 | missing_texts 非空 | 缩减该页文字数量或简化措辞后重试 | 1次 |
| 构图/画面问题 | 无错字但构图偏离或大面积裁切 | 原样重试（随机化种子） | 1次 |
| 文字重复	| duplicated_texts 非空，且为关键文字 | 修正 prompt：在文字清单中强调"每段文字只出现一次，不要重复"，提高 guidance_scale 至 3.5~4.0 | 1次 |
| 混合问题 | 同时存在错字+构图问题 | 先修 prompt 再重试 | 1次 |

重试仍 FAIL 的降级策略由各链路 workflow 自行定义。

## 失败兜底

### 单张偶发失败

重试一次。重试时可以保留原 prompt，只随机化种子；若失败原因是 prompt 不合规，则先改写 prompt 再重试。

### 排版 `.pptx` / HTML 配图失败

单张重试仍失败时，该页改用原生形状、SVG 图标、色块或占位图片区，继续完成整份文档，并在执行摘要中标注降级页码。

连续多张失败或服务持续不可用时，放弃 AI 配图，整份 deck 使用原生组件替代图片素材。

### 图片 PPT 失败

图片 PPT 的核心内容依赖生图。单张失败时保留页码和叙事结构，用原生占位页或常规排版页兜底。连续多张失败时停止流程，向用户说明情况并让用户选择切换到排版 PPT、网页演示或放弃生成。

## 常见错误处理

| 错误 | 处理 |
|------|------|
| 缺少 prompt | 补充最终 prompt 后重试 |
| 缺少参考图 | 使用图生图模式时必须提供参考图片 |
| 参考图格式不支持 | 转换为 png、jpg、jpeg 或 webp |
| 参考图路径不可访问 | 检查路径、权限和文件是否存在 |
| 额度限制类错误 | 停止生图，告知用户当前状况并请其选择降级方案。额度每日重置，不得基于记忆推断额度已耗尽 |
| 内容不符合安全要求 | 改写 prompt，避免敏感或违规描述 |
| 服务暂时不可用 | 单次重试；持续失败则降级 |
