

# 图片 PPT 创建工作流

本文档用于创建“每页一张 AI 生成完整图片”的 `.pptx`。该路线追求快速视觉成稿，但图片内文字、图表和数据不可编辑，且可能需要重生成修正。

## 适用边界

适合：

- 一次性演示、快速出图、概念提案、视觉草案。
- 低文字、强视觉、海报式、发布会式内容。
- 用户明确接受图片中文字和图表不可编辑。

不适合：

- 精确数据、表格、KPI、财务数字、公式。
- 长中文段落、专有名词密集、品牌法务文本。
- 需要后续多人编辑和复用模板的正式汇报。

如用户内容明显不适合图片 PPT，先建议切换到排版 `.pptx`。除非用户坚持，不要继续图片 PPT 路线。

## 必读文件

开始执行前必须阅读：

1. `references/shared/content-planner.md`
2. `references/shared/image-gen.md`
3. 选定风格文件：`references/image-pptx/styles/*.md`
4. `references/pptx/pptxgenjs-api.md`

## 总流程

```text
确认路线、风格、主题、页数
  ↓
规划页面大纲和页面类型
  ↓
组装逐页 prompt
  ↓
逐页调用生图能力
  ↓
用 PptxGenJS 组装 .pptx
  ↓
生成 thumbnail 做视觉 QA
```

## Step 1 · 规划页面

如果用户只给大主题，先拆成 N 页大纲。若生图服务返回额度或可用性限制，再请用户减少页数、分批生成，或切换到排版 PPT / 网页演示路线。

页面类型必须从以下四类中选择：

| 类型 | 用途 | 典型内容 |
|------|------|----------|
| `cover` | 封面 | 标题、副标题、主视觉 |
| `content` | 正文观点页 | 核心观点、2-3 个短要点、概念解释 |
| `data` | 数据氛围页 | 少量指标、趋势、对比，但不承诺精确渲染 |
| `closing` | 收束页 | 总结、行动号召、联系方式 |

输出一张规划表：

| 页码 | 页面类型 | 页面主题 | 可见文字 | 视觉重点 | 风险 |
|------|----------|----------|----------|----------|------|

如果某页“可见文字”太长，先压缩内容。建议：

- 标题不超过 14 个中文字。
- 每页要点不超过 3 条。
- 每条要点不超过 12 个中文字。
- 精确数字不要超过 3 个。

## Step 2 · 选择风格

用户选择的风格直接对应一个风格文件：

| 用户选项 | 风格文件 |
|----------|----------|
| 商务专业 | `styles/business-pro.md` |
| 杂志编辑 | `styles/magazine-editorial.md` |
| 科技未来 | `styles/tech-future.md` |
| 极简海报 | `styles/minimal-poster.md` |
| 数据可视化 | `styles/data-viz.md` |

每个风格文件都包含：

- 风格 ID
- 适用场景
- 基础提示词模板
- `cover` / `content` / `data` / `closing` 页面类型模板

## Step 3 · 组装 Prompt

最终 prompt 由四部分组成：

```text
风格基础模板
+ 页面类型模板
+ 页面具体内容
+ 文字清单和位置约束
+ 16:9 尺寸与负面约束
```

每页 prompt 必须明确列出：

- 要生成的页面类型。
- 画面中允许出现的文字清单。
- 每段文字的大致位置。
- 主标题、副标题、要点之间的层级关系。
- 禁止额外文字、乱码、水印、伪 logo。

固定后缀：

```text
生成 16:9 横向幻灯片画面，适合作为整页 PPT 背景图。只出现上述文字清单中的文字，不要生成额外标题、页码、水印、伪 logo、版权标记、乱码或无意义字符。画面四周保留安全边距，重要文字不要贴边。
```

关键文字准确性强调（当页面含必须精确渲染的文字时 MANDATORY）：

在固定后缀之后追加：

```text
所有文字必须与上述清单逐字一致，不得出现形近替换、同音替换、偏旁增减或拼写错误。
【重点文字】（必须精确渲染）：{从文字清单中选取人名、专有名词、品牌词、精确数字等，标注常见混淆}
```

```

当校验发现错字并触发修正重试时，必须将 wrong_chars 中的错字以相同格式追加到此区域。

## Step 4 · 生图

调用 `references/shared/image-gen.md` 中的生图能力。纯图片 PPT 默认使用：

- 文生图模式
- 16:9 比例，推荐尺寸 `2560x1440`（见 `references/shared/image-gen.md` 推荐尺寸表）
- `n=1`
- `guidance_scale=2.5`
- `seed=-1`
- 输出目录：`{工作目录}/.temp/images/`

关键封面可用 `n=2` 到 `4` 生成候选；若服务返回额度限制，减少候选数或改为单张生成。

推荐命名：

```text
{工作目录}/.temp/images/slide-01.png
{工作目录}/.temp/images/slide-02.png
```

风格一致性：

- 所有页面共用同一风格基础模板。
- 如需参考图，优先使用无文字风格样张，不要直接用正文页成品图作参考。

失败处理：

- 单张失败：重试一次。
- 重试仍失败：保留该页，用原生占位页或常规排版页兜底。
- 连续多张失败：停止图片 PPT 流程，告知用户现状并询问是否切换到排版 PPT、网页演示或放弃生成。

### 图像校验

所有图片生成完毕后、组装 `.pptx` 之前，使用图像理解能力对每张图片进行校验。校验可并行执行。

校验提示词模板、页面类型附加检查、status 判定标准和基本重试规则详见 `references/shared/image-gen.md` 的"图像校验"章节。生图服务默认的合规水印不算校验失败，详见同文件的「合规水印（生图服务默认）」。以下仅列出图片 PPT 链路特有的降级策略。

**校验结果分级处理（图片 PPT 特有）：**

| status | 处理 |
|--------|------|
| PASS | 继续 |
| WARN | 记录问题，继续组装，不重试 |
| FAIL | 按 `references/shared/image-gen.md` 的 FAIL 类型执行对应重试策略；仍 FAIL 则按以下兜底策略处理 |

### 图片 PPT 兜底策略（按优先级）

**优先级 1：精简文字后重新生图**

当页面文字较多导致错字概率高，或重试后仍有个别错字时：
- 减少要点数量，或缩短每条文字
- 重新生成，走完整校验流程
- 仅允许1次精简重试

**优先级 2：原生占位页**

精简重试后仍 FAIL、构图严重偏离或大面积乱码等无法修复的情况：
- 用 PPT 原生组件重建该页内容（标题、要点、简单背景色）
- 在执行摘要中标注降级页码

**连续失败熔断：** 校验连续 3 页 FAIL，停止生图流程，通知用户当前状况并询问是否切换到排版 PPT 或网页演示路线。

**封面页特殊规则：** 封面 FAIL 重试后仍 FAIL，直接通知用户选择降级或切换路线（封面是门面，不适合降级为占位页）。

## Step 5 · 组装 `.pptx`

每张图片作为一页全屏背景。优先使用 `slide.background`，如环境兼容性不稳定，使用 `slide.addImage()` 铺满全页。

**强制约束**：`addImage` 的 `w × h` 必须等于 `pres.layout` 对应的幻灯片物理尺寸（英寸）。生图 size 的宽高比必须与 layout 宽高比一致。违规将导致图片溢出裁切或黑边变形。

### Layout 与生图尺寸对照表

| 生图 size | 比例 | `pres.layout` | 幻灯片尺寸 | `addImage` w × h |
|-----------|------|----------------|------------|-------------------|
| 2560×1440 | 16:9 | `LAYOUT_16x9`  | 10"×5.625" | 10 × 5.625        |
| 2560×1440 | 16:9 | `LAYOUT_WIDE`  | 13.3"×7.5" | 13.333 × 7.5      |
| 2240×1680 | 4:3  | `LAYOUT_4x3`   | 10"×7.5"   | 10 × 7.5          |
| 3024×1296 | 21:9 | 自定义 layout   | 需自定义    | 需自定义           |

### 通用兜底规则

以下三条规则比例无关，适用于对照表未覆盖的任何生图尺寸：

**规则一：比例三方一致性**

生图 size 的宽高比、`pres.layout` 的宽高比、`addImage` 的 w/h 比，三者必须完全一致。只要有一项不匹配，就会溢出裁切或黑边变形。生成前必须验证：

```
abs(生图宽/生图高 - addImage_w/addImage_h) < 0.01
```

不通过则报错，不允许继续。

**规则二：尺寸精确匹配**

`addImage` 的 `w × h` 必须等于 `pres.layout` 对应的幻灯片物理尺寸（英寸），不是"大约"，是"等于"。对照表里的值是查出来的，不是估算出来的。

**规则三：未知比例的自定义 layout 兜底**

如果生图比例不在对照表中，用 `defineLayout` 自定义一个与图片比例一致的 layout，然后 w/h 取该自定义 layout 的尺寸：

```javascript
// 示例：生图比例 7:3，不在预设 layout 中
const imgRatioW = 7, imgRatioH = 3;
const slideHeight = 7.5; // 英寸，可自定义
const slideWidth = slideHeight * (imgRatioW / imgRatioH); // = 17.5

pres.defineLayout({ name: 'CUSTOM_7x3', width: slideWidth, height: slideHeight });
pres.layout = 'CUSTOM_7x3';
// ...
slide.addImage({ path: '...', x: 0, y: 0, w: slideWidth, h: slideHeight });
```

推导公式：已知图片比例 `R = imgW/imgH` 和目标幻灯片高度 `H`，则 `W = H × R`。

### 代码示例

使用 `slide.background`（优先）：

```javascript
pres.layout = 'LAYOUT_WIDE'; // 必须与下方 w/h 匹配
// ...
slide.background = { path: ".temp/images/slide-01.png" };
```

兼容写法（`slide.addImage`）：

```javascript
pres.layout = 'LAYOUT_WIDE'; // 必须与下方 w/h 匹配
// ...
slide.addImage({
  path: ".temp/images/slide-01.png",
  x: 0,
  y: 0,
  w: 13.333,  // LAYOUT_WIDE 的精确宽度（英寸）
  h: 7.5      // LAYOUT_WIDE 的精确高度（英寸）
});
```

禁止再叠加 PPT 原生文字。若图片中文字错误，应重生成该页，而不是在 PPT 上补文字层。

## Step 6 · QA

必须生成 thumbnail 预览图进行视觉检查：

```bash
mkdir -p "{工作目录}/.temp/qa"
python scripts/thumbnail.py "{工作目录}/output.pptx" "{工作目录}/.temp/qa/output-thumbnails" --cols 4
```

如环境缺少 LibreOffice / Poppler 导致 thumbnail 失败，必须在执行摘要中标注“未能完成自动预览 QA”。

检查项：

- 页数与规划一致，没有静默减少页数。
- 每页都有全屏图片，没有空白页。
- 图片铺满 16:9 画布，没有黑边、拉伸变形或关键内容裁切。
- 多页风格一致。
- 图片内文字可读，没有明显乱码、错字或伪 logo；生图服务默认合规水印可忽略，不算 QA 问题。
- 数据页没有把不可靠的复杂表格或精确图表当成最终结果。

QA 通过后，`.pptx` 链路的 `.temp/images/` 可按需清理；QA 前不要删除源图片。
