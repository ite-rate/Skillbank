# PPT 创建、编辑和分析

## 概述

当用户要求创建、编辑、读取或整理演示文稿时使用本 skill。创建新演示文稿时支持三条交付路线：

- 排版 PPT（`.pptx`）：兼容 PowerPoint / Keynote / WPS，文字、图表、形状等对象可编辑；可选 AI 配图作为素材。`.pptx` 文件本质上是 ZIP 压缩包，包含 XML 文件和其他资源；`.ppt` 是旧版 PowerPoint 格式，需要先转换为 `.pptx`。
- 网页演示文件（`.html`，有外部图片时包含 `images/` 目录）：视觉表现力强，支持 WebGL 背景和入场动效；需浏览器查看和修改，且仅支持预设主题色。
- 图片 PPT（`.pptx`）：每页是一张 AI 生成的完整图片，视觉质量高但页面文字和图表不可编辑；不适合精确数据、表格、长中文或后续协作编辑。

## 启动前资源检查

启动本 skill 后，执行任何 PPT 创建或编辑步骤前，必须先检查当前 skill 目录下的 SVG template 资源状态：

1. 若存在 `svg-templates/` 目录：资源已就绪，按正常流程继续。
2. 若不存在 `svg-templates/` 目录但存在 `svg-templates.zip`：先在当前 skill 目录解压 `svg-templates.zip`，确认生成 `svg-templates/` 后删除 `svg-templates.zip`，再继续执行。
3. 若两者都不存在：停止执行并告知用户 SVG template 资源缺失。

## 需求澄清

### 快速通道

如果用户同时满足以下 4 项，跳过全部澄清，直接进入路由执行：

1. 明确指定输出路线（排版 PPT、网页演示或图片 PPT）。
2. 提供完整大纲。
3. 提供模板或明确要求的风格。
4. 指定 ppt 篇幅和信息呈现偏好。

如果不满足快速通道，必须进入最多两轮的澄清流程。

### 最多两轮澄清

#### 第一轮：只确认输出路线

仅当用户既没有明确输出路线，也没有提供模板/现有 PPT 时，第一轮只问一个问题：

**注意**： 用户说“帮我做一个ppt/演示文档”，不算是指定生成`.pptx`格式

```markdown
你希望这次交付为哪种形式？

- **排版 PPT**（`.pptx`）：全可编辑、兼容性好，适合汇报、课件、提案和后续协作。
- **网页演示**（`.html`，有图片时包含 `images/` 目录）：视觉表现力强，适合线下演讲和发布会；仅支持预设主题色。
- **图片 PPT**（`.pptx`）：AI 生成完整页面，视觉质量高；但文字和图表不可编辑，复杂数据可能有误。
```

第一轮禁止同时询问视觉风格、主题色、受众、时长、素材或硬性约束。

如果用户已经明确输出路线，或已经提供模板/现有 PPT，则跳过第一轮：

- 明确说 `.pptx` / 可编辑的演示文稿 → 视为排版 PPT 路线。
- 明确说网页演示 / HTML  / 典雅画报风网页 PPT / 简约商务风网页 PPT → 视为网页路线。
- 明确说纯图 PPT / 图片 PPT / 每页一张图 → 视为图片 PPT 路线。
- 提供模板或现有 `.pptx` / `.ppt` 文件 → 视为排版 PPT 路线，不再询问输出格式。


#### 第二轮：一次性收集所有缺失项

输出路线明确后，第二轮一次性询问该路线下仍缺失的所有待确认项。用户已经明确说过或可稳定推断的信息不要重复问。

第二轮之后不得继续追问。若用户仍未回答完整，使用合理默认值继续，并在执行前的配置摘要中标注“未提供，按默认处理”。

### 第二轮确认项

如果 `#1 = 排版 PPT`：

- 视觉风格：商务简约、科技专业、正式庄重、温润亲和、高端品牌、中国风、自定义。
- 主题色：可根据既有 `.pptx` 设计体系推荐，也可接受用户指定色值或品牌色。
- 视觉素材来源：已有自备图片/图表/截图、需要 AI 生成、不需要图片。
- 视觉偏好（可不选，默认 A）：
  - **A · 改着顺手，Agent 综合判断**（默认）— Agent 以可编辑性为优先目标，在可行范围内兼顾视觉质量，将创意集中在排版、配色、字体层面；全部内容保证可编辑。
  - **B · 偏视觉，Agent 综合判断** — Agent 以视觉表现为优先目标，综合内容类型、演示场合和风格要求决定最合适的方案；多数内容可编辑，少数视觉效果型元素可能为嵌入式。
  - **C · 全程可编辑** — 所有文字、图表、表格均可在 PowerPoint / WPS / Keynote 中直接修改，适合后续频繁协作和内容调整；若内容包含桑基图、瀑布图等特殊图表，届时会说明。
  - **D · 视觉冲击为主** — 设计自由度高，支持复杂版式和高级图形效果；文字内容均可编辑，少数高复杂度图形为嵌入式图元，不支持在 PPT 内直接拖拽修改。

如果 `#1 = 网页演示文件`：

- 视觉方案（风格与主题色已绑定，不接受单独指定主题色）：
  - **典雅画报风**：
    - 墨水经典（通用 / 商业发布 / 默认）
    - 靛蓝瓷（科技 / 研究 / 数据）
    - 森林墨（自然 / 可持续 / 文化）
    - 牛皮纸（怀旧 / 人文 / 文学）
    - 沙丘（艺术 / 设计 / 创意）
  - **简约商务风**：
    - 克莱因蓝（汇报 / 路演 / 科技 / 默认）
    - 柠檬黄（活力 / 消费 / 零售）
    - 柠檬绿（生态 / 新兴 / 未来）
    - 安全橙（工业 / 警示 / 运动）

如果 `#1 = 图片 PPT`：

- 每页主题：用户提供逐页描述，或只给一个大主题由 Agent 拆分。
- 图片风格：商务专业、杂志编辑、科技未来、极简海报、数据可视化。
- 页数：用户指定或由 Agent 根据时长推断；若生图服务返回额度限制，再请用户减少页数、分批生成或切换路线。
- 页面文字：由生图模型直接生成，文字和图表不可编辑；若内容包含精确数据、表格、KPI、长中文或品牌法务文本，必须建议切换到排版 PPT。

除此之外，三种路线均需要确认以下细节：

- 应用场景与受众：如部门例行汇报、领导班子专项汇报、技术分享/培训、商业提案/路演、年度/季度总结、行业观察/研究分享。
- 演示时长或页数：参考 5-10 分钟约 5-8 页，15 分钟约 10 页，30 分钟约 20 页，45 分钟约 25-30 页。
- 信息呈现偏好：文字叙述为主、图表可视化为主、图文并重、由 Agent 根据场景判断。
- 内容来源：已有原始素材、已有要点、只有主题需 Agent 组织大纲。
- AI 配图方案（排版 PPT / 网页演示适用，图片 PPT 跳过此项）（单选），请注意你必须在选项中向用户说明生图额度消耗的风险：
  - **不需要**：纯文字与原生组件
  - **精简配图**：1-2 张关键配图（推荐，大多数场景够用）
  - **精简 + 候选**：精简配图，关键主视觉生成多张候选选最佳（效果更好，额度消耗约翻倍）
  - **多配图**：所有适合放图的页面各 1 张 AI 配图（生图额度消耗较多）
  - **多配图 + 候选**：多配图 + 关键主视觉多张候选（额度消耗极大）
  - 若用户有自备图片/图表/截图，可在本项之外另行说明，与 AI 配图不互斥。
- 硬性约束：必须包含/不得出现的内容、保密要求、页数上限、特定结构、品牌规范等。

**网页视觉方案确认话术（硬约束）**：当用户已选择或已确定为网页演示文件（HTML 类 PPT），且视觉方案尚未确认时，必须按风格分组呈现所有可选方案，让用户一次性选定风格 + 主题色组合，避免风格与主题色错配。

向用户确认视觉方案时，优先使用下方标准话术（可按上下文微调措辞，但不得删掉分组结构和场景说明）：

```markdown
请选择网页演示的视觉方案（风格与主题色绑定）：

**典雅画报风**：大图 + 衬线标题，偏人文叙事。
- 墨水经典 — 通用 / 商业发布 / 不知道选啥的默认
- 靛蓝瓷 — 科技 / 研究 / 数据
- 森林墨 — 自然 / 可持续 / 文化
- 牛皮纸 — 怀旧 / 人文 / 文学
- 沙丘 — 艺术 / 设计 / 创意

**简约商务风**：版式规整、数字醒目，偏信息清晰。
- 克莱因蓝 — 汇报 / 路演 / 科技 / 不知道选啥的默认
- 柠檬黄 — 活力 / 消费 / 零售
- 柠檬绿 — 生态 / 新兴 / 未来
- 安全橙 — 工业 / 警示 / 运动
```

| 如果用户说... | 推荐方案 |
|---|---|
| "典雅画报风" / "杂志感" / "人文" / "Monocle 风" / 不指定 | 典雅画报风 · 墨水经典 |
| "简约商务风" / "瑞士风" / "Swiss Style" / "Helvetica" / "极简" / "网格" / "信息图" / "数据驱动" | 简约商务风 · 克莱因蓝 |

**禁止行为**：不得在风格未确定时单独列出某个风格的全部主题色让用户先选色再匹配风格——这会导致风格与主题色错配。


### 澄清执行规则

1. 澄清最多两轮，严禁追加第三轮。
2. 第一轮只在输出路线无法从用户输入或模板/现有文件中推断时触发，且只能问输出路线。
3. 第二轮一次性提出所有缺失确认项；可以用多个问题块，但必须同轮发出。
4. 用户已提供或可基于上下文推断的信息不要重复询问。
5. 用户未回答的项目用合理默认值继续，并在配置摘要中标注默认值。
6. **网页路线 + 需确认视觉方案时**：必须按风格分组呈现所有可选方案（风格 + 主题色绑定组合），不得先列某一风格的全部主题色再让用户选风格；违反视为澄清不合格。

## 路由

### 创建排版 `.pptx`

适用：用户需要标准 PowerPoint 文件，或需要后续编辑、协作、套模板、兼容办公软件。

#### 引擎路由清单（内部执行，不告知用户）

**走 SVG**（视觉表现力更强）：
- 视觉偏好 **D** — 始终 SVG，无例外
- 视觉偏好 **B** + 含复杂图表（SVG-only 图表：桑基/瀑布/漏斗/旭日/弦/复杂雷达等）或视觉风格偏高端/中国风/炫彩科技

**走 PptxGenJS**（全可编辑）：
- 视觉偏好 **A** — 始终 PptxGenJS，无例外
- 视觉偏好 **C** — 始终 PptxGenJS，无例外
- 视觉偏好 **B** + 全是标准图表（柱/折/饼/散/表格）且风格为商务简约/正式庄重/温润亲和

> 遇到 SVG-only 图表但走 PptxGenJS 时（A / C 选项），告知用户「该图表将以可编辑方式近似实现，数值和文字均可编辑」。

不得向用户提及「SVG」「PptxGenJS」「DrawingML」等技术词汇。

#### 入口 workflow

- 走 **PptxGenJS**：完整读取 `references/pptx/create-workflow.md`
- 走 **SVG**：完整读取 `references/pptx-svg/create-workflow.md`

只读取入口 workflow，后续 reference 由各 workflow 按阶段和条件指引读取。

### 编辑 `.pptx` / `.ppt`

适用：用户提供现有 PPT 并要求改文字、调结构、替换内容、分析备注/批注、处理表格/甘特图/复杂形状。

必须完整读取：`references/pptx/edit-workflow.md`。

只读取这个入口 workflow。复杂结构编辑、OOXML、旧版 `.ppt` 转换等下游 reference 由 `edit-workflow.md` 按条件指引读取。

### 创建网页演示文件

适用：用户明确选择网页演示文件、典雅画报风 PPT、简约商务风 PPT、horizontal swipe deck，或更看重视觉表现而非后续 Office 编辑。

必须完整读取：`references/html/gen-workflow.md`。

### 创建图片 PPT

适用：用户明确选择图片 PPT、纯图 PPT、海报式 PPT、每页一张 AI 生成图片，或明确接受页面文字和图表不可编辑。

必须完整读取：`references/image-pptx/workflow.md`。

只读取这个入口 workflow。后续需要哪些 reference，由 `workflow.md` 按阶段和条件指引读取。


### 读取 / 分析 PPT

如果只是读取或分析内容，可先使用快捷命令：

```bash
python -m markitdown path-to-file.pptx
```

需要备注、批注、母版、动画、复杂格式或 XML 级结构时，读取 `references/pptx/edit-workflow.md` 并使用 OOXML unpack 流程。

## 关键风险

| 链路 | 跳过 reference 的典型后果 |
|---|---|
| `.pptx` 从零创建 | PptxGenJS API 用错、主题对象不一致、页面类型单一、中文字号和标点不合规。 |
| `.pptx` 模板创建 | 模板页索引错误、占位符数量不匹配、文字被清空或溢出、格式属性丢失。 |
| `.pptx` 编辑 | 表格/甘特图结构错乱、group shape 坐标误判、条形与表格行不对齐、文字被截断。 |
| 网页·典雅画报风（风格 A） | 发明模板不存在的类名、主题节奏单调、图片比例错误、动效兜底资源缺失。 |
| 网页·简约商务风（风格 B） | 未遵守 S01-S22 登记版式、缺失 `data-layout`、标题居中误用、SVG 内写文字、校验失败。 |
| AI 配图 | 生图服务额度或可用性受限、图片风格不一致、在图片内生成关键文字或精确数字，导致内容不可控。 |
| 图片 PPT | 把不可编辑图片误当标准 PPT、复杂中文或数据渲染错误、未做 thumbnail QA。 |
| 澄清不足 | 输出路线、页数、受众或素材假设错误，导致返工。 |

## 注意
1. **「PPT」≠ 默认排版 `.pptx`**：本场景中用户说的「PPT」「演示文稿」可能指 **排版 `.pptx`、旧版 `.ppt`、网页 HTML、图片 PPT** 任一种交付形态，不要因用户只说「做个 PPT」「PPT 文件」「幻灯片」等就默认按排版 `.pptx` 创建；输出路线未明确时必须走澄清流程确认。
2.  **禁止凭记忆或历史偏好决策**：严禁根据对话记忆、过往会话或上下文中的历史选择（如上次做过网页 PPT、常用某风格/主题色）推断本次输出格式、路线、风格或其他配置；本次用户未明确说明的一律向用户确认，不得擅自默认。
